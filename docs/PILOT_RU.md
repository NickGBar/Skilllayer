# Пилот SkillLayer: с чего начать

Для команды, которая согласилась попробовать. Читается минут за десять,
ставится минут за пятнадцать.

**Статус: прототип.** В продакшене у нас пока никто не стоит, сертификата ФСТЭК
и записи в реестре российского ПО нет. Пилот бесплатный и совместный: нам нужны
ваши числа не меньше, чем вам — наш инструмент.

## Что делает

Проверяет изменение перед тем, как оно попадёт в рабочую ветку, и не верит
агенту на слово:

- **тесты** — прогоняет сам, а не читает чужой отчёт; упало и прошло на повторе
  считается флаки, а не проходом;
- **целостность тестов** — замечает, если набор ослаб: тест удалён, ассерт
  выкинут, добавлен `skip`, понижен порог покрытия;
- **закрытые зоны** — путь, защищённый политикой, не изменён;
- **секреты** — ключ, добавленный в любом коммите диапазона, даже если следующим
  коммитом его удалили;
- **ваши проверки** — любая команда, которую вы назовёте обязательной.

Проверка, которая не выполнилась, никогда не считается пройденной: нет тестов,
сломалось окружение, не уложились в таймаут — это отдельный исход, и он тоже
не даёт зелёного.

После каждого прогона остаётся расписка: какие коммиты судились, что
запускалось, что вернуло, какие пути изменились, кто и что одобрил руками.

## Чего не делает

- **Не ищет уязвимости.** Это работа сканеров. Мы следим, чтобы сканер
  действительно отработал, и записываем результат.
- **Не читает код за вас** и не пишет замечания в PR.
- **Не судит о замысле.** Туда ли положено, то ли сделано, понятны ли имена —
  это по-прежнему ревьюер.
- **Не заменяет ревью.** Убирает из него то, что до него не должно было дойти.

## Что понадобится

- Репозиторий на git и команда тестов, которая запускается одной строкой.
- Python 3.10 или новее на машине, где пойдёт проверка.
- Один репозиторий для начала. Не весь ваш код — один.

## Шаг 1. Установка

```bash
pipx install git+https://github.com/NickGBar/Skilllayer.git@v0.3.0
```

Метка `v0.3.0` фиксирует версию на весь пилот: всё, что мы посчитаем, будет
относиться к одной версии. Обновляемся, только когда договоримся.

Проверить:

```bash
skilllayer --version   # 0.3.0
skilllayer gate --help
```

## Шаг 2. Прогон вручную, в режиме наблюдения

Сначала на своей машине, ничего не блокируя:

```bash
cd /путь/к/репозиторию
skilllayer gate --base origin/main --mode warn --lang ru
```

`--mode warn` только отчитывается. Ничего не блокируется, в репозиторий ничего
не пишется.

Если тесты запускаются нестандартно, скажите чем:

```bash
skilllayer gate --base origin/main --mode warn --lang ru \
  --test-command "make test"
```

## Шаг 3. В CI, по-прежнему в режиме наблюдения

Возьмите готовый файл:

- GitHub Actions — [`examples/gate/github-actions.yml`](../examples/gate/github-actions.yml)
- GitLab CI — [`examples/gate/gitlab-ci.yml`](../examples/gate/gitlab-ci.yml)

В скопированном файле поставьте ту же версию, что в шаге 1: в строке
`pip install` замените `git+https://github.com/NickGBar/Skilllayer.git` на
`git+https://github.com/NickGBar/Skilllayer.git@v0.3.0`. Иначе CI поставит
последнюю версию из `main`.

Суть одна:

```bash
skilllayer gate --base "$BASE_SHA" --author "$PR_AUTHOR" --mode warn --lang ru \
  --receipt-dir gate-receipts --event-log gate-receipts/events.jsonl
```

**Задачу обязательной пока не делайте.** Две недели она просто пишет, что
поймала бы.

Если у вас уже есть сканер или линтер, который должен быть обязательным,
добавьте его сюда — тогда станет видно и то, как часто он не отрабатывает:

```bash
  --check "sast=semgrep scan --error"
```

## Что вы увидите

Отчёт в консоли на русском (`--lang ru`) и по строке на прогон в
`events.jsonl`. Ключи в журнале и в расписках всегда английские, чтобы правила
SIEM и скрипты читались одинаково на любом языке.

Коды выхода: `0` принято или изменений нет, `2` заблокировано бы, `3` проверить
не удалось, `1` ошибка самого инструмента.

Расписки складываются в `gate-receipts/` у вас. Наружу ничего не уходит:
ни кода, ни имён, ни статистики. Подробности — [TELEMETRY_PRIVACY.md](TELEMETRY_PRIVACY.md).

## По ходу пилота: разметить срабатывания

Третье число ниже — сколько срабатываний ложные — без вас не посчитать: только
ваша команда знает, была ли остановка по делу. На случай уходит пара минут.
Удобно размечать раз в несколько дней, пока подробности свежие.

**1. Соберите расписки в одну папку.** Скачайте артефакты `gate-receipts` всех
прогонов CI в одну папку, например `~/skilllayer-pilot/`. Расписки ручных
запусков можно положить туда же. Ваша разметка будет храниться в этой же папке,
не удаляйте её между сессиями.

**2. Посмотрите, что сработало:**

```bash
skilllayer cases list --receipt-dir ~/skilllayer-pilot --lang ru
```

Одна строка — один случай: номер, дата, коммит, проверка с её статусом и ваша
оценка.

```
c-58cae29743  2026-11-30  3f2a9c1e7d4b  test_integrity:failed  [не размечен]
```

**3. Оцените каждый случай:**

```bash
skilllayer cases label c-58cae29743 --verdict correct --fixed yes --minutes 8 \
  --receipt-dir ~/skilllayer-pilot
```

- `--verdict correct` — остановить изменение по этой причине было правильно:
  проблема настоящая.
- `--verdict false_positive` — остановка лишняя: проблемы не было.
- `--verdict unsure` — не можете решить. В долю ложных не входит.
- `--fixed yes` или `no` — исправили ли изменение из-за этого случая.
  Необязательно.
- `--minutes 8` — сколько минут человек потратил на разбор и исправление.
  Необязательно, но без этого не посчитать, сколько времени проверка экономит
  или отнимает.
- `--note "…"` — одна строка до 300 символов, остаётся у вас. Ключи и пароли
  туда не пишите.

Передумали — запустите `label` для того же случая ещё раз: учитывается последняя
оценка.

**Как решать по типам проверок:**

| Что в списке | Верно (`correct`) | Ложно (`false_positive`) |
|---|---|---|
| `tests:failed` | тест упал из-за ошибки в изменении | упал из-за окружения или внешнего сервиса, а не из-за изменения |
| `test_integrity:failed` | тест или проверку действительно ослабили | тесты поменяли осознанно и правильно, например удалили тест убранной функции |
| `secrets:failed` | это настоящий ключ, токен или пароль | тестовое или выдуманное значение |
| `protected_paths:failed` | правка закрытой зоны требовала согласования | путь не стоило закрывать — тогда поправьте политику |
| статус `not_verified` | проверка не выполнилась по вине изменения | не выполнилась из-за окружения CI; часто честнее поставить `unsure` и оставить заметку |

Проверки `agent_scope` и ваши собственные (`check:…`) оценивайте по тому же
принципу: была ли проблема настоящей.

**4. Сводка:**

```bash
skilllayer cases summary --receipt-dir ~/skilllayer-pilot --lang ru
```

Расписки при разметке не меняются: оценки дописываются в отдельный файл
`labels.jsonl` в той же папке. Наружу ничего не уходит.

## Через две недели: на что смотреть вместе

Ровно четыре числа. Их мы и обсудим на встрече.

1. **Сколько раз сработало бы** — то есть сколько изменений уехало в ветку,
   не пройдя обязательных проверок.
2. **По какой причине** — красные тесты, ослабленный набор, секрет, закрытая
   зона, ваша собственная проверка.
3. **Сколько ложных** — сколько срабатываний вы считаете неправильными. Это
   самое важное число: оно решает, можно ли включать блокировку.
4. **Сколько стоил прогон** — минуты в CI.

Все четыре показывает `skilllayer cases summary`: строки «Остановил бы»,
«Причины», «Доля ложных среди оценённых» и «время гейта». Третье появится, только
если случаи размечены.

Если первое близко к нулю — у вас всё и так хорошо, и мы честно это скажем.
Это нормальный исход пилота, и он тоже полезен обеим сторонам.

## Если решите включить всерьёз

Убрать `--mode warn` и сделать задачу обязательной. Тогда изменение, не прошедшее
проверки, не вливается.

Там, где решает человек — осознанно удалили тест, обдуманно тронули закрытую
зону, — отдельная задача CI передаёт одобрение, и оно попадает в расписку:

```bash
  --approve-test-changes    # удаление теста согласовано
  --approve-protected       # правка закрытой зоны согласована
  --approve-scope           # агент вышел за свою зону, и это согласовано
```

Ключ `SKILLLAYER_RECEIPT_KEY` держите в защищённой переменной CI: тогда расписку
запечатывает подпись, которую проверяемый код прочитать не может.

## Проверка во время работы агента

Отдельно от CI есть проверка прямо в сессии агента: когда он собирается
закончить, запускаются тесты, и при красных он разворачивается и чинит сам —
до того, как человек открыл PR.

Для Claude Code — [CLAUDE_CODE_SETUP.md](CLAUDE_CODE_SETUP.md),
подробности — [VERIFY.md](VERIFY.md).

Это та часть, которая экономит время ревьюера напрямую, и её стоит включить
второй, когда ворота в CI уже постояли неделю.
